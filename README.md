# Планер — менеджер задач

Десктопное приложение на Python для планирования задач. Интерфейс построен на Tkinter, локальные данные хранятся в SQLite, а синхронизация устройств работает через JSON-файл в общей облачной папке. Интерфейс использует темно-синюю шапку, бирюзовый акцент и системные шрифты Aptos/Segoe UI с автоматическим выбором доступного варианта. Для запуска и тестирования не нужны сторонние Python-пакеты.

## Возможности

- создание, просмотр, редактирование и удаление задач;
- отметка выполнения и возврат задачи в активные;
- поиск по названию, описанию и категории;
- категории, приоритеты и срок выполнения;
- фильтры по статусу, категории и приоритету; сортировка по сроку, дате создания, приоритету или названию;
- напоминания о задачах со сроком сегодня или в прошлом, пока приложение открыто;
- регистрация, вход и выход из пользовательского профиля; списки задач разных профилей изолированы;
- сохранение данных в локальной базе SQLite между запусками;
- синхронизация задач, изменений, статусов и удалений между устройствами через общий файл.

Пароли хранятся локально в виде солёных PBKDF2-HMAC-SHA256 хешей; пароль и хеши не попадают в файл синхронизации. Профиль нужно создать отдельно на каждом компьютере, используя одно и то же имя пользователя для синхронизации его задач.

Для синхронизации нажмите **«Настроить файл»** и выберите файл `planer-sync.json` в общей папке OneDrive, Google Drive или другом каталоге, который синхронизирует файлы между устройствами. Обмен выполняется при входе, после изменения задачи и автоматически примерно раз в 30 секунд; также доступна кнопка **«Синхронизировать»**. Данные объединяются по идентификаторам задач, при конфликте применяется последняя версия по времени изменения, а удаления передаются как tombstone-записи.

Синхронизация полагается на облачный клиент, который доставляет файл на другое устройство; отдельный сервер не требуется. Изменения задач хранятся в JSON без шифрования, поэтому используйте приватную облачную папку и не сохраняйте в задачах секреты. Из-за ограничений одновременной записи файловых облачных клиентов не редактируйте одну и ту же задачу одновременно на нескольких устройствах; при редактировании офлайн нажмите синхронизацию после подключения к сети. Встроенные учётные записи локальны и не заменяют серверную аутентификацию для публичного сервиса.

## Требования

- Python 3.10 или новее;
- настольная среда с Tkinter (обычно входит в установку Python).

Внешние зависимости не используются.

## Запуск

Откройте терминал в папке проекта и выполните:

```powershell
python app.py
```

База создается автоматически при первом запуске. Расположение: `%LOCALAPPDATA%\Планер\tasks.db` в Windows, `~/Library/Application Support/Планер/tasks.db` в macOS или `$XDG_DATA_HOME/Планер/tasks.db` (по умолчанию `~/.local/share/Планер/tasks.db`) в Linux. Если на компьютере уже есть база предыдущей версии, приложение продолжит использовать ее из папки `TaskFlow`, чтобы сохранить задачи.

Срок указывается в формате `ГГГГ-ММ-ДД`, например `2026-12-31`. Чтобы не задавать срок, оставьте поле пустым. Дважды щелкните задачу, чтобы открыть редактирование. Напоминание показывается при запуске и затем примерно раз в минуту; одна и та же задача не повторяется в напоминаниях в рамках текущего сеанса.

## Тесты

Запуск полного набора автоматических тестов:

```powershell
python -m unittest -v
```

Тесты проверяют создание и валидацию, редактирование, статусы, удаление, поиск, фильтрацию, сортировку, восстановление после повторного открытия базы, авторизацию и изоляцию пользователей, слияние синхронизации и распространение удалений.

## Архитектура

- `app.py` — окно Tkinter, диалог задачи, фильтры, пользовательские действия и напоминания.
- `tasks.py` — модель задачи, проверка данных, локальная авторизация и хранилище SQLite.
- `sync.py` — проверка и атомарная запись JSON-файла синхронизации.
- `test_tasks.py` и `test_auth_sync.py` — автоматические тесты задач, авторизации и обмена файлами.

Пользовательский интерфейс отделен от хранения: экран вызывает методы `TaskStore`, а репозиторий отвечает за SQLite и валидацию. `AuthStore` проверяет локальные учётные данные. `SyncService` объединяет записи по неизменяемым UUID и времени изменения; отметки об удалении не дают удалённым задачам появляться вновь при последующем обмене. Пароли и данные авторизации не экспортируются.
